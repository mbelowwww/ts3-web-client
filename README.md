# ts3web

Веб-клиент для TeamSpeak 3: админка через ServerQuery + двусторонний голос через WebRTC.
Контекст, архитектура и разбор решений — в [`ts3-web-client-plan.md`](./ts3-web-client-plan.md).

Реализован первый вертикальный срез (план, §7.1–7.4): единый пароль на сайт,
админка (дерево каналов, модерация), приём и передача голоса между браузером
и TS3-каналом (на каждого веб-юзера поднимается отдельный TS3-клиент).

## Установка

```bash
npm install
cp .env.example .env
# заполнить переменные, см. таблицу ниже
npm run dev
```

Откройте `http://localhost:3000` — браузер спросит логин/пароль (HTTP Basic
Auth); логин можно ввести любой, пароль — значение `TS3_SERVER_PASSWORD`.

### Тестовый TS3-сервер в Docker

Если под рукой нет боевого TS3-сервера, поднимите тестовый:

```bash
docker compose up -d
docker logs ts3web-test-server
```

В логах при первом запуске будет строка вида:

```
Server Query Admin Account created
loginname= "serveradmin", password= "<сгенерированный пароль>"
```

Впишите его в `TS3_QUERY_PASSWORD`, и укажите `TS3_HOST=127.0.0.1`,
`TS3_QUERY_PORT=10011`, `TS3_QUERY_PROTOCOL=raw`, `TS3_VOICE_HOST=127.0.0.1`.
Тестовый сервер по умолчанию не требует пароля подключения — `TS3_SERVER_PASSWORD`
в этом случае используется только как пароль входа на сайт.

## Переменные окружения (`.env`)

| Переменная | Назначение |
|---|---|
| `PORT` | Порт веб-сервера (по умолчанию 3000) |
| `TS3_HOST` | Адрес TS3-сервера (используется и для ServerQuery, и как умолчание для голоса) |
| `TS3_QUERY_PORT`, `TS3_QUERY_PROTOCOL` | Порт/протокол ServerQuery: `10011`+`raw` (telnet) или `10022`+`ssh` |
| `TS3_QUERY_USER`, `TS3_QUERY_PASSWORD` | Логин/пароль **ServerQuery** (админ-доступ к серверу, НЕ пароль подключения обычного клиента) |
| `TS3_QUERY_NICKNAME` | Ник, под которым видна ServerQuery-сессия админки |
| `TS3_VOICE_HOST`, `TS3_VOICE_PORT` | Адрес/порт голосового (виртуального) сервера, по умолчанию порт `9987` |
| `TS3_SERVER_PASSWORD` | Пароль подключения к серверу (обычный, не ServerQuery) — двойное назначение: (1) отдаётся TS3 при заходе каждого голосового моста, (2) единственный пароль входа на сайт (HTTP Basic Auth, см. ниже) |
| `TS3_BRIDGE_NICKNAME_PREFIX` | Префикс ника для голосовых мостов, поднимаемых на каждого веб-юзера |

## Аутентификация

Один пароль на весь сайт — HTTP Basic Auth, проверяется на каждый запрос
(статика, `/ws/admin`, `/ws/voice`) в `src/server.ts`. Логин игнорируется,
проверяется только пароль — он должен совпадать с `TS3_SERVER_PASSWORD`.
Отдельного секрета для сайта заводить не нужно: значение переиспользуется
из уже существующего пароля подключения к TS3-серверу.

Браузер запоминает Basic-креды на весь origin после первого успешного входа
и сам подставляет их в последующие запросы, включая WebSocket-апгрейды —
дополнительный код на фронте не нужен.

## Деплой на прод (без домена — только IP)

Пошаговая инструкция с проверкой каждого шага — в [`DEPLOY.md`](./DEPLOY.md).

Коротко: всё поднимается одной командой —

```bash
docker compose -f docker-compose.prod.yml up -d --build
```

Это разворачивает три контейнера: TS3-сервер, гейтвей и nginx. Домена нет —
только IP, поэтому Let's Encrypt не подходит; TLS терминирует nginx с
самоподписанным сертификатом, который генерируется автоматически при первом
старте контейнера (`deploy/nginx-entrypoint.sh`). Сервисы обращаются друг к
другу по именам внутри docker-сети (`ts3server`, `ts3web`), без
`network_mode: host` и без ручной установки nginx на хост. Наружу
публикуются только `80`/`443` и голосовой `9987/udp` — порты гейтвея (3000)
и ServerQuery (10011) наружу не смотрят вообще.

Единственное ручное действие после первого запуска — вписать в `.env`
реальный пароль ServerQuery, который TS3 сгенерирует сам при первом старте
(см. `DEPLOY.md`, шаг 3).

## Структура

```
src/
  config.ts               загрузка и валидация .env
  server.ts                Fastify: Basic Auth хук, раздаёт public/, WS-эндпоинты /ws/admin и /ws/voice
  admin/serverQuery.ts      обёртка над ts3-nodejs-library (ServerQuery)
  voice/voiceBridge.ts      один TS3-голосовой клиент (honeybbq) + werift RTCPeerConnection на юзера,
                            приём и передача голоса
  voice/voiceSessions.ts    реестр активных голосовых сессий по WS-соединению
public/                     тестовая страница без сборки (голое JS + WebRTC)
docker-compose.yml          TS3-сервер (образ teamspeak:latest) для локальной разработки — сам по себе, без гейтвея
docker-compose.prod.yml     прод одной командой: TS3 + гейтвей + nginx(TLS) в одной docker-сети
Dockerfile                   multi-stage сборка гейтвея (tsc build → node dist/server.js)
deploy/
  nginx.conf.example          конфиг nginx (self-signed TLS, проксирование на ts3web:3000 по имени сервиса)
  nginx-entrypoint.sh          автогенерация самоподписанного сертификата при первом старте контейнера
```

## Известные риски / что проверить дальше

См. §6 и §8 `ts3-web-client-plan.md`. Коротко:

- **VAD/индикация говорящих не реализованы.** Есть ручная кнопка
  вкл/выкл микрофона (`#toggleMic` в `public/index.html`), но нет ни
  автоматической детекции тишины (VAD), ни push-to-talk по горячей клавише,
  ни визуальной индикации того, кто сейчас говорит.
- **Identity генерируется заново на каждую сессию** (`generateIdentity(8)` в
  `voiceBridge.ts`). Для прода стоит выдавать/сохранять identity на пользователя,
  иначе каждое переподключение — новый "клиент" для TS3-сервера.
- **TURN-сервер (coturn) не настроен** — без него пользователи за строгим NAT
  не подключатся к голосу. Нужен перед продом.
- **`@honeybbq/teamspeak-client` (0.2.x) — молодая библиотека.** Работает в
  тестах, но по зрелости уступает C#-ной TSLib — возможны шероховатости на
  крайних случаях (см. ts3-web-client-plan.md, §6).
- **HTTP Basic Auth сама по себе не шифрует пароль** (base64, не шифрование) —
  обязательно нужен HTTPS/wss поверх (см. план, §6). Раздел "Деплой на прод"
  выше закрывает это через nginx + TLS (self-signed при деплое без домена).

### Уже проверено и работает
- Приём и передача голоса между браузером и TS3-каналом — подтверждено и
  синтетическим Node-тестом (`scratch-voice-send-test.mjs`, два "поддельных
  браузера" на `werift`+`ws` в одном канале), и вживую в браузере.
- `payloadType` для Opus в `voiceBridge.ts` больше не захардкожен — берётся
  из реально согласованного `transceiver.codecs`.
- `public/admin.js` и `public/voice.js` выбирают `ws:`/`wss:` динамически по
  `location.protocol` — под HTTPS (прод) не ловят mixed-content блокировку.

## Скрипты

- `npm run dev` — запуск с автоперезагрузкой (tsx watch)
- `npm run build` — компиляция в `dist/`
- `npm start` — запуск собранной версии
- `docker compose up -d` — тестовый TS3-сервер для локальной разработки
